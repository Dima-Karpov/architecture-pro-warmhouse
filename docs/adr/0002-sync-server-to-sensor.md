# ADR-002: Синхронный опрос датчика сервером

- Status: Accepted
- Date: 2026-09-04
- Deciders: команда разработки «Тёплый дом»

## Context

Жилец должен видеть текущую температуру и включать отопление. У устройств нет своего канала «в облако»: установка делает специалист, управление идёт от сервера к датчику. В монолите уже есть синхронный HTTP-клиент к `temperature-api`. Нагрузка сейчас — сотни модулей, не поток событий.

## Decision

Монолит сам ходит в датчик/реле по запросу пользователя: читает температуру и отправляет команду on/off. Устройство не пушит телеметрию. Брокер в As-Is не используем.

## Alternatives considered

- Push с датчика — нет прошивки и канала; пользователь сам датчик не подключает.
- Очередь (Kafka / MQTT) — лишняя операционка для 5 человек и 100 модулей; нет события, которое нужно развязать.
- Опрос из браузера напрямую в датчик — ломает единый контур доступа и не совпадает с кейсом «сервер → датчик».

## Consequences

- Positive: простой запрос-ответ, проще отладка, совпадает с текущим кодом.
- Negative: рост числа домов упрётся в синхронные вызовы; падение датчика сразу бьёт в ответ API; нет истории событий.
- Follow-up: в To-Be телеметрию вынести в свой контур; пересмотр ADR, когда появится self-service и устройства партнёров.
