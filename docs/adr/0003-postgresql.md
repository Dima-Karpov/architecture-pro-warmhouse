# ADR-003: PostgreSQL как единственное хранилище As-Is

- Status: Accepted
- Date: 2026-09-04
- Deciders: команда разработки «Тёплый дом»

## Context

Нужно хранить реестр датчиков и последнее состояние (значение, статус, `last_updated`). Команда работает с SQL, в шаблоне уже есть `init.sql` и `pgx`. Объём — сотни устройств, нет требования к аналитике и шардам. Пользователь и дом в схеме ещё не выделены.

## Decision

Единственное хранилище монолита — PostgreSQL. Отдельные БД на домен в As-Is не заводим.

## Alternatives considered

- SQLite в процессе приложения — хуже для нескольких инстансов и привычного операционного контура.
- Документная БД — нет выигрыша: модель плоская (`sensors`), нужны обычные выборки по `type` / `location` / `status`.
- Файлы или in-memory — потеря состояния при рестарте, нет индексов.

## Consequences

- Positive: один операционный контур, ACID на запись датчика, готовый скрипт инициализации.
- Negative: телеметрия и реестр устройств делят одну БД — при выносе сервиса понадобится разделение данных.
- Follow-up: в задании 3 добавить User / House / Device; отдельная БД на сервис — только вместе с выносом bounded context.
