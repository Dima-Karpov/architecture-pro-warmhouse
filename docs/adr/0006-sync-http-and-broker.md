# ADR-006: Синхронный HTTP между сервисами, брокер только для телеметрии сценариев

- Status: Accepted
- Date: 2026-09-04
- Deciders: команда разработки «Тёплый дом»

## Context

Жилец ждёт ответ в том же запросе: включить отопление, открыть ворота, посмотреть температуру. Сценарий «если t° → команда» срабатывает от потока показаний, его не должен тормозить браузер. Сервисы не шарят БД ([ADR-004](0004-db-per-service.md)). Команда маленькая: два контура связи проще, чем шина на всё.

## Decision

Сервисы общаются так, как на Container. Не через чужую БД и не «все в Kafka».

**Синхронно, HTTP JSON** — когда вызывающий ждёт результат:

- жилец → Web UI → API Gateway → `user-house` / `device` / `command` / `telemetry` / `scenario`
- `command` → `device` — взять тип и адрес, потом команда на прибор
- `scenario` → `command` — выполнить правило
- монолит → `device` / `telemetry` — переход в задании 6

**Асинхронно, брокер** — когда получателей много или вызов не должен блокировать запись показания:

- `telemetry` публикует показание
- `scenario` читает и решает, звать ли `command`

Ручная команда жильца в брокер не идёт: нужен 200/409 в том же запросе.

## Alternatives considered

- Всё через брокер — жилец не получит понятный отказ «устройство inactive» без отдельного статуса и таймаута; для 5 человек рано.
- Только HTTP, без брокера — сценарии начнут поллить `telemetry`; пик показаний ударит в оба сервиса сразу.
- Сервис читает чужую Postgres — дешевле на черновике, убивает границу контекста.
- gRPC между сервисами — быстрее на бумаге (бинарный HTTP/2). Для курса нет доказанной нагрузки; задание 4 просит OpenAPI/Swagger; монолит в задании 6 говорит HTTP. Два стека (REST наружу + gRPC внутрь) не окупаются пятью людьми. Оставим HTTP JSON.

## Consequences

- Positive: ручное управление остаётся request/response, как As-Is; сценарии не держат HTTP жильца; на схеме сразу видно, кто кого зовёт.
- Negative: два стиля интеграции (синхрон + async) — два контракта в задании 4 (OpenAPI и AsyncAPI).
- Follow-up: задание 6 может поднять `device` и `telemetry` по HTTP без брокера; брокер на схеме — задел, не блокер MVP. Если появится второй подписчик на телеметрию — брокер обязателен в коде.
