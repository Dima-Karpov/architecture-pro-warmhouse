# ADR-005: Новые приборы — DeviceType, не отдельный сервис

- Status: Accepted
- Date: 2026-09-04
- Deciders: команда разработки «Тёплый дом»

## Context

Кейс To-Be: отопление, свет, ворота, наблюдение и ещё неизвестные датчики партнёров. Комплекты продают отдельно, протоколы стандартные. Команда — 5 человек. Если на каждый тип прибора завести сервис, появятся light-service, gate-service и новый сервис на каждого партнёра.

## Decision

Один сервис `device` держит реестр. Тип прибора — сущность `DeviceType` (`heating`, `light`, `gate`, `camera`, `unknown`). Один сервис `command` шлёт on/off/lock любому типу. Новый партнёр = новая строка типа и адаптер протокола, не новый деплой.

## Alternatives considered

- Сервис на каждый тип (отопление, свет, ворота, камера) — закрывает тендер «в лоб», но ломает неизвестные датчики и не тянется силами пяти человек.
- Один «умный дом» сервис на все домены — снова монолит под другим именем.

## Consequences

- Positive: неизвестный датчик не требует новой команды и нового репозитория; задание 6 выносит только `device` + `telemetry`.
- Negative: `command` знает много типов — риск толстого switch. Если один тип начнёт жить своей командой (свой цикл, своя команда), его вынесем отдельным ADR.
- Follow-up: ER задания 3 — `Device.type_id`; на Container не рисовать light/gate как контейнеры.
